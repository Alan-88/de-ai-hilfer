# 主搜索框中文反查与候选扩容：执行计划

状态：已进入实施。执行结果和验证边界见 `2026-10-20-chinese-search-candidates.md`；以下保留经确认的实施范围与验收依据。

## 目标与已确认边界

在主查词搜索框直接输入中文，使用现有 embedding 实时返回已初始化的德语词汇候选。德语搜索沿用词头、词形、别名与近似拼写逻辑。两种候选都扩容，并保持有限高度、内部滚动。

- 使用现有 glm-embedding-3 和 dictionary_lexeme_embeddings；不要求中文文本入向量，不重建索引，不引入翻译或生成模型重排。
- 中文只检索已初始化的 knowledge_entries 对应 lexeme；德语保留原词典覆盖范围。
- 现有 Tab / 联想线索开关、附加输入栏、intelligent_search 路由与功能语义保留。用户明确要求，未再次讨论前不得合并、替换或迁移到该入口。
- 主搜索首页和查词结果页展开搜索都适配；不顺带改词库列表搜索或文章快捷查词栏。共享API默认行为需兼容这些调用方。
- 中文候选实时刷新；点击指定候选打开该词，回车沿用默认第一候选，不新增确认步骤。
- 德语与中文均首批展示20条，每次“加载更多”增加20条，最多100条。候选数量不得撑长PC或移动页面。
- 不扩展MCP/CLI工具。本轮检查共享契约是否受影响，记录检查结果；未来是否开放语义工具另行讨论。

## 实测依据

2026-10-20 已调用现有渠道，不需要用户提供新密钥。已初始化2,232词全部有2048维向量，完整词典仍为94,098个lexeme。20条中文查询的预定目标词第一名9/20、前五17/20、前十17/20；这是探索样本的指定目标排名，不是普遍准确率。

- “减肥”→abnehmen第1；“城堡”和“门上的锁”→Schloss第1；“收据”→Kassenzettel第1、Quittung第5。
- “公园里坐的长椅”→Bank第18；“和医生约好的见面时间”→Termin第24；“预约”→Termin第49。需要足够长的候选列表。
- “辞职”把Quittung排到第1，kündigen第3；无意义输入也会有近邻。排序仍可能错误，不能将分数当正确概率。
- 单条embedding实测234/290/306ms；查询脚本中位168ms含Docker/psql启动，不代表真实网页端到端耗时。
- 对3个历史摘要重新嵌入，与旧向量相似度均>0.999995，未发现向量空间不兼容。
- 旧infer_headword_by_embedding的0.36/0.45距离阈值会拒绝本轮全部中文首选；新列表只按距离排序，不复用其唯一词头阈值或领先幅度条件。

本地复现资料：output/embedding-probe-20261020.md、.json、.mjs，以及output/embedding-compat-probe-20261020.mjs。脚本直接读取既有配置，不含硬编码密钥，数据库查询只读。这些文件尚未提交；执行者不得把它们误判为无关垃圾或直接批量提交整个output目录。资料丢失时，以本节作为交接基线。

## 实施步骤

### 1. 候选接口与检索

先搜索所有getSuggestions、get_suggestions及候选响应调用者，再做兼容扩展。

- 建议复用GET /api/v1/suggestions，增加可选mode=lexical|semantic与limit；缺省仍为lexical、10条，上限100。主搜索显式请求100条，其他调用者保持原默认行为。参数在后端校验并限制长度、数量。
- 保留现有suggestions响应与DBSuggestion主要字段，尽量复用既有知识库预览构造逻辑，不返回完整解析或向量。
- semantic分支：按当前持久配置调用embedding，验证向量非空、维度与索引可用；仅查询有已初始化知识条目且有同模型向量的lexeme，过滤必须在排序/截断前完成。按距离、稳定次序排序，避免重复词条，最多100条。
- 返回真实entry_id、query_text和已有中文释义预览，使点选打开已有词条。沿用现有身份语义；若同词多entry，明确稳定选择，不能混用lexeme_id与entry_id。
- 不调用analyze、initialize或intelligent_search来获取候选。模型失败、索引模型不匹配、无可用向量等应有明确错误/空状态，不能悄悄切到生成。
- lexical分支扩大各来源合理取数和最终限制，保留现有排序、去重、大小写和词形解析规则；不能只扩大最终10条而仍被上游10/20条截住。不要为凑满100条改变原精确词形优先语义。
- 不新增服务端分页缓存：每次有效查询一次取回最多100条，前端分批展示。加载更多不发新embedding请求；前端候选只需保存当前查询快照。

### 2. 输入分流与请求生命周期

- 使用Unicode汉字属性（如/\p{Script=Han}/u）判断是否进入semantic；不要按ASCII判断。Straße、übernehmen、Ärger、größer、ẞ等走lexical；含汉字的混合输入把整段作为semantic查询，不增加专用混合语言解析器。
- 空输入保留原最近查询；单字中文“爱”“税”可查；德语原字符门槛保留，不把拼音组合态当德语搜索。
- 监听compositionstart/end和isComposing；拼音组合期间不查、不提交，确认汉字后触发查询。处理Safari/移动端事件顺序，避免组合结束与input重复请求，避免选字Enter顺带提交表单。
- 中文使用约200ms防抖；输入变化、清空、失焦、卸载等妥善清理计时器和请求。请求版本号/查询快照与AbortController一起防止旧结果和旧错误覆盖新状态，包括A→B→A场景。
- 加载时保留旧候选以减少闪动，但旧候选必须标识为过期、不能在新查询按回车时被默认选中。主查询提交等待/取得当前输入的有效候选后再选第一条；不再次重复发出相同的在途embedding请求。
- 中文查询失败或没有候选，保留输入并显示可重试状态；不得把原中文送入德语初始化。点选已经确认的德语候选应按原流程打开，不再被中文分流重定向。
- 收起搜索后迟到响应不得重新打开面板。切换中德文时清理候选展示计数；200ms内连续输入只提交最终有效文本。
- 保持当前Tab联想/Escape/返回/聚焦置顶动画；组合输入期间不拦截输入法所需按键。

### 3. 候选数量与固定高度（核心验收项）

- 一次拿到最多100条，初显20条；“加载更多”置于列表末尾，每次显示20条，直到耗尽或100条。少于20条直接完整显示；不伪造总数，不在耗尽后仍显示更多。
- 追加候选保留列表scrollTop与输入焦点，不重复计算向量、不跳回顶部。更换查询后，结果有效替换时重置为20条和列表顶部。
- 搜索输入栏和候选标题不随候选内容滚走；候选列表是唯一纵向滚动区，加载更多入口可在其底部触达。无需额外一层滚动容器或虚拟列表。
- 沿用桌面候选列表420px视觉高度上限；实际可用高度更小时继续收缩。容器使用flex纵向布局和min-height:0，标题不收缩，列表可收缩并overflow-y:auto。
- 面板总高度同时受可见视口约束。按visualViewport的offsetTop+height与面板实际顶部计算可用空间，扣除安全边距、标题/边框及确实占位的底部导航；不要只依赖100vh/dvh或断点固定减数。注意坐标系一致，避免键盘与安全区重复扣减。
- 手机键盘弹出、收起、横竖屏变化以及PC窗口变矮时更新约束；空间不足时不得用强制min-height撑出视口。保留既有visualViewport监听，只有必要时补布局测量。
- 面板外层约束高度与overflow:hidden，列表内部滚动；不能仅裁切外层，让底部候选/加载更多永远无法触达。桌面滚轮与移动触摸均能滚列表，列表边缘不把背景页面继续推走。
- 列表从20扩到40/100条，不得增加面板高度或document/主页面滚动高度；不得产生横向溢出。顶部搜索、关闭/返回、主题开关、底部导航与键盘不遮住可操作内容。
- 覆盖首页聚焦和结果页展开搜索两种结构。截图需等布局/主题过渡结束，不能把过渡中的混色当最终效果。
- 样式使用canvas/canvas-dark token，组件布局留在Svelte；不改变现有字号、胶囊外形或做额外视觉改版。

### 4. 验证与交付

有意义的自动化覆盖：

- 汉字/德语特殊字符/混合输入/单字中文分类，composition期间零查询和零提交，composition结束只触发一次有效查询。
- 延迟乱序、旧失败、清空、关闭、卸载、中德切换、A→B→A；过期候选不能被新查询回车选中。
- semantic只返回已初始化条目；模型与维度不匹配、超时等不触发写库；最多100、无重复、排序稳定。可用隔离数据库/模拟embedding，不能在生产构造数据。
- lexical超过10/20条的实际前缀样例，确认上游未提前截断，现有词形/大小写回归通过；旧调用方默认10条兼容。
- 20→40→100的数量、滚动位置与面板几何断言；“加载更多”不产生新候选HTTP请求或embedding调用。

真实浏览器检查与截图：

- 桌面1280×900、较矮桌面900×650；移动390×844、320×568、横屏844×390，首页和结果页展开搜索。
- 两套主题，20条与展开更多状态；滚至列表末尾能看见并使用最后候选/更多按钮，页面尺寸不增长。
- 键盘弹出/收起与中文选字确认。可自动化验证composition事件和缩小可见区域，但桌面浏览器模拟不等同真实手机键盘；无法实机验证的部分必须在交付中明确，不能宣称已通过。
- 复用既有真实中文查询样本，确认如“预约”的Termin可在后续候选找到。语义排序会随模型略波动，不把实时准确名次写成脆弱单元断言。
- 保留修改前后截图于output/playwright/，最终回复直接展示涉及界面截图，并说明真实网络的查询耗时与未知项。

## 完成标准

用户在同一个主搜索框输入中文即可实时浏览已初始化词汇；德语候选扩容且旧排序语义保持；PC/移动端最多100候选始终在有限高度内滚动、键盘出现也可操作；原联想搜索入口和行为通过回归；无中文误初始化、重复分页embedding调用或过期请求串结果。已提供真实截图、验证记录和部署状态。
