# 移动查词搜索栏与标题比例初调

用户发现移动搜索按钮不居中，搜索框左右边距不一致，要求结合已有移动字号与留白经验做初步调整。本轮改动集中在SearchPageView，不扩展到结果正文或其他页面。

## 原因与调整

- 原移动按钮通过font-size:0隐藏“分析”文字，但flex仍保留0.6rem间距，浏览器测量图标向左偏4.8px。文字改用独立span并在移动断点display:none，按钮和生成/取消覆盖层gap归零，搜索图标18px。保留圆形44×44px按钮。
- 原结果态将返回箭头独立固定，搜索框为其预留3.5rem左侧空间，手机上搜索框左边距72px、右16px。返回按钮移入搜索行，移动端以44px命中区参与排版，搜索框全宽并与正文卡片左右16px对齐；PC仍采用原固定返回位置。
- ≤768px输入16px、行高区域44px，行容器内距6px/8px，搜索框总高度58px（原74px）。清空/联想工具宽32px、高44px；联想输入16px，展开栏采用相同纵向密度。上下圆角继承搜索面板，避免20px面板与28px输入行不匹配。
- ≤600px首页标题26px/1.2，居中，与已验证的移动结果词头26px同尺度；辅助说明12px/1.5，标题到搜索框间距16px。首页上方间距随视口高度在40–96px间变化，结果页搜索栏下方间距16px。
- 建议标题14px、简介12px，条目内距10px/12px，保留滚动、点击、键盘与原搜索业务逻辑。

## 维护

- 只重建frontend，未重启backend/MCP；无API、CLI或Skill契约变更。
- 检查current-state、active-roadmap与iterations；更新状态与本记录，无优先级变更。
- 改前/改后截图保存在output/playwright/rich-responsive-references/search-chrome-{before,after}-{width}-{theme}-{home,result,advanced}.png，覆盖320/390/600/768/1280px及双主题。捕获脚本同时测量按钮中心、两侧边距、输入字号与横向溢出，分析响应使用浏览器fixture，其他写请求拦截。
- 未在实体手机与Safari验证触控与软键盘；16px输入字号保留移动输入可读性。

## 验证

- npm run check为0错误、2项已有SearchPageView警告，生产镜像构建通过。
- 双主题下320/390/600/768/1280px的首页、结果页与联想展开态完成30张改前和30张改后截图。移动搜索图标横纵偏移均为0（原横向-4.8px）；左右边距均为16px；单行高度58px，联想展开总高115px，未出现横向溢出。PC搜索框尺寸和居中位置与改前一致。
- 首页与结果状态的返回按钮实际点击检查通过。所有分析响应均由浏览器fixture返回，未触发真实生成或其他业务写入。
- 补充320/390/1280px的挂起请求与取消分析检查，移动取消图标同样居中；390px滚动后搜索栏位置不变、返回按钮可命中、清空输入及Tab展开/Escape收起联想通过。

## 跟进：标题错排与框内留白

- 用户要求保留PC主标题/说明左右错开的方向。≤600px主标题恢复靠左，说明靠右，标题组左右内缩16px；26px/12px字号与纵向间距保留。窄屏缩减错开距离，不采用PC的固定14rem说明偏移。
- 初调时提示文字左内距与搜索按钮右内距实测均8px，虽然数值相等，文字仍显得靠近圆角。≤768px主输入行两侧均增至16px，纵向6px和58px总高度保持。框外距屏幕16px与框内16px分别控制。
- 改前截图沿用search-chrome-after-*；本次首页截图为search-title-insets-{width}-{theme}.png，结果截图为search-title-insets-result-320-{theme}.png。检查active-roadmap，无优先级变化，纯前端布局变动不涉及CLI/MCP。
- 双主题320/390/600/768/1280px浏览器检查完成；≤600px标题保持单行，≤768px说明统一靠右，输入两側内距16px且图标居中；320px结果态输入宽度94px，无横向溢出。类型检查0错误、2项原有警告，生产构建通过，仅更新frontend容器。
