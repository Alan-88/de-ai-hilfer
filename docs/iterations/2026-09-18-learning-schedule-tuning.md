# 2026-09-18 学习日内调度策略收口

## 背景

学习 V3 已经区分“首次反馈的长期 FSRS”与“后续反馈的日内复现”。本轮重点不是重写记忆模型，而是修正时间等待、刷新恢复和活动卡数量之间的关系。

## 方案

- 首次反馈立即写入长期 FSRS；当天后续评分不再改写长期排程。
- 日内复现以 `earliest_review_at` 为主，`due_after_seen` 只在可复现卡片之间做排序。
- 活动日内工作集以 `10` 张作为软上限，不是每日新词上限：
  - 未满且没有到期日内卡时，继续引入已加入学习的新词。
  - 达到上限后，如果暂时没有卡片到时间，按最近到期卡片做数量降级回放。
- 单卡当天最多出现 `6` 次；首答为“忘记”的卡片，后续答对后再等待 `5` 分钟，以避免短时记忆刚恢复就立即结束当天循环。
- 普通日内间隔保持为：忘记 `45 秒`、模糊 `2 分钟`、认识 `1 分钟`。
- 刷新或后端重启后，从当天 `learning_review_logs` 恢复首答为“模糊/忘记”且尚未满足完成条件的卡片；仅恢复卡片状态，不恢复原内存游标。
- 没有立即可展示卡片时，接口返回 `next_available_at`，前端等待后再请求下一张，不把等待态当作 session 完成。

## 取舍

`10` 是活动工作集的降级阈值，不承担科学参数的含义，也不限制每天能开始多少新词。它只是防止用户回答过快时无限引入新词，同时尽量不破坏时间间隔。是否需要调整，应先看真实使用日志，不先增加 CLI 调参入口或复杂的数据库时间队列。
